# AI Gateway

Единственная точка вызова LLM во всей системе (тех. ТЗ 1.2, 5). Домены Core API
никогда не обращаются к YandexGPT или GigaChat напрямую — только к этому
сервису по внутреннему адресу.

Наружу не публикуется: порт доступен только внутри docker-сети, эндпоинты живут
под префиксом `/internal`. Поэтому в сервисе нет CORS — браузер сюда не ходит.

```
src/navigator_ai/
  config.py        настройки: провайдер, ключи, таймауты, TTL кэша
  logging.py       логи; сервис независим и не тянет пакет navigator
  cache.py         клиент Redis для кэша идентичных запросов
  deps.py          зависимости FastAPI: настройки и активный провайдер
  providers/       интерфейс провайдера, заглушка, выбор по конфигурации
  main.py          сборка приложения, пробы
```

## Запуск

```bash
uv sync
uv run uvicorn navigator_ai.main:create_app --factory --reload --port 8100
uv run pytest
```

## Состояние

Готово: интерфейс провайдера с учётом расхода токенов, детерминированная
заглушка `mock`, выбор провайдера конфигурацией, пробы живости и готовности,
проверка ключей на старте.

По плану работ шлюз делается последним: он улучшает тексты, но не создаёт
функциональность. Осталось сделать вместе с блоками, которые его используют:

- реализации YandexGPT и GigaChat, повтор и фолбэк с основного на резервный
  (тех. ТЗ 5, п. 2–3);
- шаблоны промптов на Jinja2 — правки формулировок не должны требовать
  передеплоя (тех. ТЗ 5, п. 1);
- кэш идентичных запросов в Redis на короткий TTL (тех. ТЗ 5, п. 4);
- эндпоинты `/internal/ai/career-explanation`, `/internal/ai/moderate-question`,
  `/internal/ai/classify-ticket`;
- журнал стоимости запросов (тех. ТЗ 5, п. 5).

## Открытый вопрос: где хранить журнал стоимости

Тех. ТЗ 5, п. 5 требует логировать стоимость каждого запроса «в отдельную
таблицу». Таблица означает базу, а на схеме сервисов (тех. ТЗ 1.4) у AI Gateway
доступа к PostgreSQL нет. Варианты:

1. Дать шлюзу отдельную схему в том же PostgreSQL — быстро, но появляется вторая
   точка доступа к базе.
2. Писать расход в структурированный лог, а агрегировать снаружи — не требует
   базы, но история живёт только в логах.
3. Возвращать расход в ответе (уже возвращается — поле `total_tokens`) и писать
   его в базу на стороне Core API — база остаётся у одного сервиса, но учёт
   размазывается по вызывающим доменам.

Решение принимается вместе с первым настоящим провайдером. До тех пор расход
считается и возвращается в ответе, но никуда не пишется.

## Заглушка провайдера

`LLM_PROVIDER=mock` отвечает мгновенно, без сети и одинаково на одинаковый
промпт. Тех. ТЗ 7 требует, чтобы система никогда не тестировалась настоящими
вызовами LLM: это нестабильно, дорого и недетерминированно. В
`ENVIRONMENT=production` заглушка запрещена — сервис с ней не поднимется, иначе
модерация вопросов в блоке 5 работала бы вслепую.
