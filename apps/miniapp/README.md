# Мини-приложение

React + Vite + TypeScript. Одна кодовая база на мобильный и десктопный клиент
MAX (ТЗ 0.2), адаптивная вёрстка, ввод мышью и клавиатурой наравне с touch.

```bash
pnpm --filter miniapp dev          # dev-сервер на :5173
pnpm --filter miniapp test         # юнит-тесты (vitest)
pnpm --filter miniapp test:e2e     # e2e (playwright), профили desktop и mobile
pnpm --filter miniapp build        # tsc --noEmit + сборка в dist/
```

Из корня монорепо то же самое доступно через `make dev-front`, `make test-front`,
`make test-e2e`.

## Стек

Зафиксирован тех. ТЗ 8.1. Отклонения от текста ТЗ, разрешённые его же оговоркой
про «рабочие ориентиры»:

| В ТЗ                          | Взято      | Почему                                                                      |
| ----------------------------- | ---------- | --------------------------------------------------------------------------- |
| React 18                      | React 19   | 19 — текущая версия; 18 отстаёт на мажор                                    |
| React Router v6 (data router) | v7         | прямой преемник того же data-router API                                     |
| Tailwind CSS                  | Tailwind 4 | конфигурация в CSS через `@theme` — ровно то, что нужно для токенов Organic |
| TypeScript последний          | 6.0        | `typescript-eslint` пока не поддерживает 7.x                                |

`@maxhub/max-ui` не используем: продукт реализует дизайн-систему Organic
пиксель в пиксель, а готовый UI-кит платформы навязал бы чужой визуальный язык
(тех. ТЗ 9.7). Требование этого пакета к React 19 на выбор версии, таким
образом, не влияет.

## Состояние

Собрана оболочка: тема Organic, `AppLayout` с безусловной кнопкой «Главное
меню», дерево из 17 роутов (16 экранов хендоффа плюс «адрес не найден»),
типизированный клиент Core API, адаптер платформы MAX и обязательный
e2e-обход всех экранов на двух профилях устройств.

Содержимое экранов — заглушки: оно приходит вертикальными срезами блоков
(PLAN.md, шаг 6). Исключение — главное меню: список разделов в нём рабочий,
иначе приложение нечем обойти руками.

## Как это устроено

```
src/
  app/        оболочка: реестр экранов, дерево роутов, layout, кэш запросов
  screens/    экраны — по файлу на экран
  shared/
    api/      типизированный клиент Core API (schema.d.ts генерируется)
    platform/ адаптер платформы MAX: initData, кнопка «назад»
    ui/       общие примитивы
```

**Реестр экранов — единственный источник дерева роутов.**
[`src/app/screens.ts`](src/app/screens.ts) не импортирует React: из него
строятся роуты и его же читает e2e-обход. Новый экран добавляется в трёх
местах — реестр, карта компонентов в `router.tsx`, файл экрана — и после этого
попадает под проверку кнопки «Главное меню» автоматически.

Экран, забытый в карте компонентов, — ошибка компиляции: карта объявлена как
`Record<ScreenId, ComponentType>`.

## Тема и шрифты

Токены дизайн-системы Organic перенесены в `src/index.css` через `@theme`,
палитра Tailwind сброшена целиком: доступны только цвета продукта (решение
Р30). Хексы в компонентах не хардкодятся.

Caprasimo и Figtree лежат в `public/fonts` и раздаются со своего домена: внутри
WebView мессенджера чужой CDN — лишняя точка отказа и лишний запрос на медленной
сети. Файлы — те же webfont-подмножества (latin и latin-ext), что подключала
дизайн-система; обе гарнитуры распространяются по SIL Open Font License 1.1,
которая такое размещение разрешает.

Обе покрывают только латиницу, поэтому кириллица штатно набирается `system-ui` —
так же, как в прототипе; настоящим Caprasimo рисуются цифры (решение Р29).

## Правила

Полный список — в [`CONTRIBUTING.md`](../../CONTRIBUTING.md), раздел
«Фронтенд». Коротко:

- server state — только TanStack Query; Zustand копий серверных данных не
  хранит;
- черновики (баллы ЕГЭ, дедлайны, позиция) переживают выход в меню через
  `sessionStorage`; прогресс профориентационного теста — намеренно нет;
- хексы не хардкодятся, только переменные темы;
- `dangerouslySetInnerHTML` запрещён правилом eslint;
- `focus-visible` обязателен на всех интерактивных элементах.

## E2E в окружениях с предустановленным браузером

Обычно браузеры ставит `pnpm exec playwright install`. Если в окружении уже есть
Chromium другой версии сборки, путь к нему передаётся переменной — загрузка не
потребуется:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium pnpm --filter miniapp test:e2e
```

## Типы API

Пишутся не руками, а генерируются из схемы OpenAPI (тех. ТЗ 8.6):

```bash
make api-types     # из корня монорепо; сервер и база не нужны
```

Схема снимается с приложения напрямую (`python -m navigator.api.openapi`), а
не с `localhost:8000` — решение Р33. Промежуточный `openapi.json` в
репозиторий не попадает, сгенерированный `src/shared/api/schema.d.ts` —
попадает.
